# 文件中心的媒体增强 v2

状态：设计方案，尚未实施。本文描述目标模型和迁移顺序；当前代码仍使用
`entries`、`media_files`、`media_items`、`media_item_files` 和 `artifacts`。

## 目标与边界

文件和目录是唯一可浏览的内容主体。媒体增强是附着在某个文件或目录上的
一份**最终展示结果**，不是另一棵电影、剧集或专辑目录树。

核心业务概念只有三类：资料库、文件条目、媒体增强。目标表名分别为
`libraries`、`files`、`medias`。现有 `entries` 在迁移初期继续承担 `files`
的职责；重命名表不是第一步，也不应该让这次模型调整触发全量文件扫描。
`jobs`、扫描断点、全文搜索索引、播放进度和缩略图缓存是运行或功能数据，
不计入这三个核心内容概念，也不承诺数据库物理上只有三张表。

约束：

- 一个文件或目录最多有一条 `medias` 记录；没有记录时使用原始名称和通用图标。
- `medias` 对文件和目录使用**相同的公共列**：`title`、`icon`、`backdrop`、
  `year`、`line1`、`line2`、`line3`。图片字段允许为空，表示无增强图片；
  它们不是只在电影或文件夹上才存在的特殊字段。
- 列表、网格、目录头部和详情页从同一个 `medias` 结果构造展示，不分别推导封面。
- 增强失败、TMDB 不可用和存储离线不影响 `files` 的浏览；离线时保留上次增强。
- 不将 NFO、`folder.jpg`、`backdrop.jpg` 等侧车文件本身伪装成电影或电视剧。

## 数据模型

目标结构示意（实际迁移时保留现有文件表名，待调用方迁完再考虑重命名）：

```sql
CREATE TABLE medias (
    file_id       TEXT PRIMARY KEY REFERENCES files(id) ON DELETE CASCADE,
    kind          TEXT NOT NULL,             -- movie, tv, episode, book, photo, audio, folder ...
    title         TEXT NOT NULL DEFAULT '',
    icon          TEXT NOT NULL DEFAULT '',
    backdrop      TEXT NOT NULL DEFAULT '',
    year          INTEGER,
    line1         TEXT NOT NULL DEFAULT '',
    line2         TEXT NOT NULL DEFAULT '',
    line3         TEXT NOT NULL DEFAULT '',
    data          TEXT NOT NULL DEFAULT '{}', -- 插件私有结构化数据，JSON
    sources       TEXT NOT NULL DEFAULT '{}', -- 字段来源/候选值，JSON
    match_locked  INTEGER NOT NULL DEFAULT 0,
    updated_at    DATETIME NOT NULL
);
```

此处 `files` 是**目标名称**，第一阶段的真实外键必须指向现有 `entries(id)`。
空字符串的 `title` 在查询层回退到 `files.name`，但创建一条增强记录时应写入
当时可显示的标题。`line1`～`line3` 是有意限制为三行的最终展示文案，不试图
枚举电影、音乐、电子书的所有属性；插件需要的更多解析信息放在 `data` 的命名空间中，
例如 `data.video`、`data.book`。它们不能替代公共展示列。

`icon` 与 `backdrop` 存稳定的**内部图片引用**，不是磁盘绝对路径或直接暴露的
TMDB URL。建议统一为 `file:<file-id>`（如 `folder.jpg`）和
`cache:<artifact-key>`（如下载海报、视频截图或 EPUB 内嵌封面）；API 解析引用并
提供图片响应。小、中、大尺寸仍由图片服务按同一引用派生。`icon` 和 `backdrop`
的语义不随条目类型改变：前者用于列表/网格封面，后者用于详情/目录头图。

例子：

| 条目 | `kind` | `title` | `icon` | `backdrop` |
| --- | --- | --- | --- | --- |
| 电影视频 | `movie` | 匹配到的片名 | TMDB 海报缓存，缺失时可用截图 | 可用的背景图 |
| 电影目录 | `movie` 或 `folder` | NFO/TMDB 片名或目录名 | `file:<folder.jpg 的 id>` | `file:<backdrop.jpg 的 id>` |
| 电视剧目录 | `tv` | 剧名 | 本地封面或海报缓存 | 本地/在线背景图 |
| 普通照片 | `photo` | 文件名或图片标题 | 自身缩略图引用 | 空 |
| EPUB | `book` | 书名 | 内嵌封面缓存 | 空 |

只有 `folder.jpg` 时，也可以为目录创建 `kind=folder` 的记录，写入 `icon`，
但不因此声称目录是一部电影。视频文件自身的 `medias` 不因为父目录有封面就
自动复制父目录的媒体身份。不同文件引用同一张图可以，但各自的展示结果仍由
自己的 `medias` 行确定。

### API 展示契约

文件列表、搜索、目录详情和文件详情都使用同一个条目展示投影。例如：

```json
{
  "id": "<file-id>",
  "name": "The.Shining.1980.mkv",
  "type": "file",
  "media": {
    "kind": "movie",
    "title": "The Shining",
    "icon": "/api/v1/entries/<file-id>/icon",
    "backdrop": "/api/v1/entries/<file-id>/backdrop",
    "year": 1980,
    "line1": "电影 · 1980",
    "line2": "",
    "line3": ""
  }
}
```

API 输出的 `icon`/`backdrop` 是解析后的同源访问地址；库内只保存内部引用。
即使本地与 TMDB 图片都存在，列表和详情也不得各自选一次图片。没有 `medias`
行时 `media` 可省略；没有特定图片时相应 URL 为空，由 UI 统一显示通用图标。
查询要支持批量读取，避免文件列表每一项单独查一次数据库。

## 插件职责与写入规则

现有 `enrichment` 插件继续按类型处理文件；新增独立的目录分析插件/任务。
文件扫描只维护文件索引并入队，Worker 负责解析和增强。插件不应直接覆盖
`medias` 整行，而是提交候选字段，由统一的 resolver 按字段合并后原子写入。

建议优先级：手工锁定 > 本地 NFO/本地图片 > 文件内嵌信息 > 在线提供方 >
文件名推断。具体到图片：电影海报优先于视频截图；目录的 `folder.jpg` 优先于
在线海报，`backdrop.jpg` 优先于在线背景。某个字段缺失时才向低优先级回退，
不能因为 NFO 没写图片就清空已有的本地封面。`sources` 按字段记录来源和
必要的候选数据，以便移除侧车文件、重匹配或手工取消锁定后重新计算；
不靠“最后运行的插件覆盖整行”决定结果。手工匹配不应被后台重扫撤销。

应以一次事务写入同一条目的标题、图片与文案。列表和详情 API 调用同一
查询/序列化路径，避免列表展示截图、详情展示海报。读取不进行 TMDB 搜索或
磁盘枚举。侧车文件删除时，在文件系统在线且目录扫描完成后重新计算相关字段；
离线不能把“暂时读不到”当成“文件已删除”。

### 文件插件

- 视频：提取技术信息；**先用 `fileinfo` 解析文件名，拿到候选标题、年份和
  季集，再用标题/年份结合资料库类型向 TMDB 查询**；生成截图和海报候选；
  只写当前视频的 `medias`。TMDB 未命中时保留可靠的文件名解析结果，
  不把未确认候选写成在线匹配。
- 图片：提取尺寸/EXIF 并生成缩略图。作为目录侧车的 `folder.jpg`/
  `backdrop.jpg` 仍是普通文件索引项，但其图片引用写入**所在目录**的
  `icon`/`backdrop`；不把它关联成一部电影或独立照片媒体。
- 电子书/PDF：提取书名、作者、内嵌封面等，写入当前文件。
- 音频：提取标签和专辑封面，写入当前文件。若将来确实需要专辑聚合，
  先定义基于文件的查询/目录展示，不预设另一棵可浏览的媒体树。

### 目录分析

目录任务由目录自身或直接子项的增删改触发；批量扫描时等目录子项提交完成再
运行，文件监控事件需去抖。分析只读已索引的子项，绝不在 API 读取路径遍历磁盘。

1. 先处理明确的本地资料：`movie.nfo`/`tvshow.nfo` 给出标题等字段；
   `folder.jpg` 写 `icon`，`backdrop.jpg` 写 `backdrop`。只有图片也允许
   图片增强，不强行猜测影视身份。
2. 电影资料库中的非根目录：忽略字幕、NFO、图片、样本和预告片后，解析
   直接子视频。仅当它们都指向**唯一的标题及兼容年份**（多段/多画质可归一）时，
   才将目录名和视频名一起作为 TMDB 候选证据。候选必须超过明确阈值且无
   歧义；目录名恰好能搜到电影，单独不构成增强依据。
3. 混合电影目录、合集目录、资料库根目录或证据冲突的目录，不写电影身份。
   本地 `folder.jpg`/`backdrop.jpg` 仍可照常应用。
4. 电视剧目录独立判断：`tvshow.nfo` 是强证据；否则结合剧名目录和下属
   剧集/季目录的季集格式，确认只有一部剧再匹配。季目录不直接套用电影规则。
5. 普通目录没有上述证据时不搜索 TMDB，不新增增强行。

目录分析允许把子文件作为**证据**，但禁止把某个视频的 `medias` 整行直接
复制到父目录。目录和文件可以命中同一个 TMDB ID，但各自拥有自己的最终增强。

## 文件名解析：参考 `fileinfo-go`

参考项目：[lsongdev/fileinfo-go](https://github.com/lsongdev/fileinfo-go)。其
`fileinfo.MediaInfo` 已覆盖标题、年份、片源、分辨率、制作组、平台、版本、季集、
语言及音视频编码；当前项目的 `media/parser.go` 更侧重 TMDB 标题和季集解析。

实施时先把两边的真实文件名样本组成表驱动测试，再选择性移植/适配
`fileinfo-go` 的 token 识别，不直接以它的 `Parse` 结果替换现有解析器：

```text
原始视频文件名
  → fileinfo 解析 title / year / season / episode / 发布信息
  → 去除发布噪声，校验候选 title / year
  → 按资料库类型搜索 TMDB，并用年份等信息验证候选
  → 命中则以 TMDB 结果增强；未命中则保留文件名候选或原始文件名
```

目录分析也可解析目录名，但目录 TMDB 搜索必须额外满足上文的内容一致性
规则，不能因为目录名碰巧能搜到结果就直接增强。

- 保留现有的中文/纯集数命名、季目录回退与 `S01E02`、`1x02` 支持。
- 吸收片源、分辨率、编码、语言等发布信息，放入 `data.video.release`，
  不把这些噪声送进 TMDB 搜索标题。
- 将 `fileinfo-go` 的字符串季集规范化为可比较的数字；发布类型与
  “movie/tv” 语义区分，不能把 `mkv` 当媒体类别。
- 增加中文名称、括号年份、多段影片、纯数字集名、动画、文件夹名与
  `folder.jpg` 等测试。解析无把握时返回低置信度，不猜测。
- 原项目只有少量解析样本；移植前应确认边界行为和依赖方式，避免把未经验证
  的分词规则直接用于全库重匹配。

## 迁移与实施顺序

本项目已有大量索引数据，因此不删旧表、不重建数据库、不要求全量扫描或
重新调用 TMDB 才能切换。

1. **契约与测试**：固定 `medias` 模型、图片引用格式、字段优先级和目录判定
   用例；为 Movies/TV Shows 的列表、网格、详情添加同源展示测试。
2. **新表与读取层**：建立以现有 `entries(id)` 为外键的 `medias`；实现单条和
   批量查询及统一图片解析。先以新接口/影子结果对照旧结果，不立即删除旧表。
3. **插件写入**：文件插件改为产生候选字段，经 resolver 写 `medias`；目录
   分析任务独立入队。保留必要的旧 API 适配，并明确迁移期唯一写入来源，
   避免两套模型互相覆盖。
4. **可恢复回填**：从现有媒体和图片缓存表按 ID 分批回填；记录游标，允许
   中断续跑。只迁移能无歧义映射到条目的数据，冲突项交给目录分析或人工复核。
   不手动修改个别影片数据来“修好”展示。
5. **读取切换**：列表、网格、详情、搜索结果、目录头部统一读 `medias`；
   对比样本及计数，验证离线状态、NFO 和图片来源。人工匹配与播放进度的
   旧 `media_id` 引用须在删除旧表前改为条目 ID 或提供兼容映射。
6. **清理旧模型**：只有在相关 API、播放状态和回滚方案都验证后，才考虑
   移除 `media_items`/`media_item_files` 等旧表。`entries` → `files` 的
   物理重命名可另做，不与媒体迁移绑在一起。

完成标准：普通文件/目录可在无增强时浏览；有增强时列表和详情标题及封面一致；
`folder.jpg`/`backdrop.jpg` 正确落在所在目录的公共字段；混合目录不会误认成
单部电影；媒体解析和目录匹配不引发重复扫描；存储离线时旧增强仍可见。
