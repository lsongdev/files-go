# 当前数据库结构

本文件记录已实现的表职责；`migrations/001_init.sql` 是建表依据。开发阶段将历史迁移压缩为一个初始化脚本，不保留旧媒体模型的读写链路。

## 保留的表

| 表 | 用途 | 保留原因 |
| --- | --- | --- |
| `entries` | 文件和目录索引 | 名称、路径、父目录、大小、修改时间、可用状态；不依赖增强即可浏览。承担设计中的 `files` 职责。 |
| `medias` | 每个条目的最终增强 | 与 `entries.id` 一对一；统一存标题、封面、背景和展示文案。插件扩展数据与字段来源使用 JSON。 |
| `libraries` | 资料库定义 | 名称和类型独立于物理文件；类型用于约束电影、电视剧等匹配。由用户配置同步。 |
| `library_sources` | 资料库的扫描范围 | 一个资料库可有多个来源，一个存储可承载多个资料库；查询和扫描都据此限定路径。合并为单个路径会限制已有配置，改成 JSON 只会转移关联查询的复杂度。 |
| `storages` | 存储及扫描状态 | 记录存储可用性、扫描代次与进度；多个资料库可以共用一个存储。路径和凭证仍由配置管理。 |
| `jobs` | 持久化后台任务 | 增强任务需要去重、重试和崩溃后恢复；与文件是否已有增强不是同一件事。 |
| `scan_checkpoints` | 本轮扫描的目录断点 | 分别记录目录枚举完成、子树扫描完成；支持中断后继续，扫描完成即清理。不能用条目存在或 `scan_generation` 推断整个子树已经扫完。 |
| `entry_search` | FTS5 全文搜索索引 | 当前搜索按文件名做前缀匹配和相关度排序；可以重建，但去掉它需要更换搜索实现。 |
| `schema_migrations` | 结构版本记录 | 启动时判断哪些迁移已经执行；由迁移执行器创建，属于数据库管理数据。 |

共 7 张业务/运行普通表、1 张全文搜索虚拟表、1 张版本记录表。SQLite 自动创建的 `entry_search_*` 是 FTS5 内部表，`sqlite_stat*` 是查询统计，不独立维护或删除。

## 已移除

- `maintenance_tasks`：一次性修复任务已退役，没有运行时调用方。
- `artifacts`：实际仅用于缩略图，文件路径已经由 `SHA256(entry.id + mtime + size + variant)` 确定，不需要再存一份映射。缩略图生成、命中检查和 HTTP 读取都直接使用这套规则；不再在每次图片读取时写数据库。
- `playback_states`：取消观看进度保存、断点续播和“继续观看”接口。保留直接播放、HLS、转码与播放器手动拖动进度；不将观看记录转存到 `medias` 或浏览器。
- `idx_entries_path`：与 `UNIQUE(storage_id, path)` 自动生成的索引重复。

`media_files`、`media_items`、`media_item_files`、`media_match_suppressions` 已在此前切换中移除。

## 缓存与现有开发库

缩略图仍保留 small / medium / large 三种尺寸。三个当前版本的缓存文件都存在且非空才算命中；文件修改或任一尺寸丢失会重新生成。图片 HTTP URL 不包含文件版本，因此使用 ETag 重新验证，防止原文件修改后继续显示旧图。已有缓存文件的键规则未变，可直接复用；缓存空间回收仍是待实现功能。

新库直接执行初始化脚本。对已完成旧 001–020 的现有开发库，在停止旧服务并备份后，仅需移除本次退役的三个表和重复索引，无需重新扫描或丢弃媒体增强：

```sql
BEGIN IMMEDIATE;
DROP TABLE IF EXISTS artifacts;
DROP TABLE IF EXISTS maintenance_tasks;
DROP TABLE IF EXISTS playback_states;
DROP INDEX IF EXISTS idx_entries_path;
COMMIT;
```

旧媒体结构尚未完成切换的库应重新构建。初始化脚本不会自动销毁既有数据库；执行上述清理后，旧服务二进制不能继续使用该库。删除的播放记录只能通过备份恢复。
