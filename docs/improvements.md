## 保留的设计原则

- 一个 Go binary、SQLite 索引／队列／人工选择，不增加 Redis、独立搜索服务或通用 DAG。
- 源媒体只读，扫描、增强和按需播放分开；浏览和分页不读取媒体文件系统。
- 同一文件顺序增强，不同文件可并发；目录只整合已有结果和本地 artwork 引用，不再次查询目录服务。
- 原生播放器控件、直接播放优先、按需 HLS；不默认预转码整部视频。
- 结构化元数据保留在 Meta；显示行由前端派生，不增加重复显示列。

## 正确性和数据保留：R1–R3、R5

`files.revision` 表示输入版本，`meta_ver` 表示算法／配置处理版本。来源更新、人工选择、显式刷新和依赖失效递增 revision。保存事务校验 ID、revision 和影响行数；过期结果丢弃，同批有效结果仍提交。

文件／目录派生结果实际变化时，才标记父目录待汇总。普通目录新增无关文件不使整个 Root 的媒体重新识别；NFO／封面影响相关文件，电视剧成员变化只重算所属 Show。目录展示变化不会反向触发子文件 Probe。

扫描通过受限目录句柄枚举，条目 stat 相对于目录句柄执行；枚举失败或只拿到部分视图时不执行该目录的增删事务。单目录协调事务失败整体回滚；完整扫描仍是逐目录提交，不是整个 Root 的全局快照。

人工选择以 `(root,path)` 单独持久化，更具体的覆盖优先。删除／重新出现及移除 Root 配置保留选择，改名／移动不自动迁移。数据库 schema v3 增加纳秒时间及重试状态；旧索引、缓存和选择均迁移，不静默重建。

## 安全读取和挂载：R4、R6、R7

- 使用 Go `os.Root` 限制路径解析，并验证 Root 在打开前后仍为同一目录。配置路径的父级属于可信配置边界，Root 本身不能是符号链接。
- 扫描不索引 symlink；读取已索引路径时，Root 内的相对链接按 `os.Root` 规则解析，绝对链接及逃逸 Root 的链接被拒绝。普通源文件必须是 regular file；Unix 以非阻塞方式打开，避免替换成 FIFO 后挂起。
- FFmpeg／ffprobe 只接受自包含容器和本地文件／管道协议，拒绝改后缀的 HLS、concat、DASH 等清单输入，防止工具继续解析其他路径／URL；MOV 外部轨道引用保持默认关闭。
- 元数据解析器读取同一个文件句柄。FFmpeg、ffprobe、pdfinfo 和 pdftoppm 通过继承的 `/dev/fd/3` 读取，避免再次打开原路径。
- 最低 Go 版本为 1.25。描述符子进程输入支持 Linux/macOS；Windows 可编译、受限 Go 文件读取可用，但外部媒体工具的描述符输入暂不支持，调用失败时不回退到不安全路径。
- Root 身份包括设备号和可选 `mount_marker` 的相对路径／内容（最多 4 KiB）。挂载变化进入 `mount_changed`，扫描和源读取均保留边界；普通浏览继续读旧索引。
- 未配置 marker 的非空 Root 突然变空时，即使设备号相同也保留索引。`POST /api/roots/{root}/scan?force=1` 明确接受当前挂载身份／空目录；配置了 marker 时仍要求 marker 存在可读。
- 扫描使用纳秒 mtime，API 的 `mtime` 仍为毫秒。底层文件系统若只提供粗时间戳，或修改同时保留大小和时间，仍不能仅凭 stat 证明内容未变；不默认对全部 NAS 媒体做哈希。

回归覆盖文件和父目录换成 Root 外链接、Root 自身链接、并发替换、受限读取交给子进程，以及 marker 内容变化、marker 丢失、force 和同设备空目录。真实卸载、NFS/SMB 断连、bind mount 等仍须在目标 NAS 验证；设备号无法替代所有挂载语义，缺少可靠设备标识时应配置独立 marker。

## 调度和资源：R8–R10

### 重试

`retry_count`、`retry_after` 和错误写入文件行，指数退避为 5 秒到 5 分钟。队列不派发尚未到期的任务；重启后保留计划，来源变化和人工刷新清除旧计划。旧 revision 的失败不能覆盖新状态。

TMDB 和 ThePornDB 分别在连续三次临时失败后冷却约 30 秒，恢复时只放行一个探测请求。本地音乐／图片任务继续执行。成功的 ffprobe JSON 缓存在 SQLite，按来源大小、纳秒 mtime、探测器和格式版本失效；网络重试复用本地探测结果。它不是通用的任意增强阶段 checkpoint 引擎。

### 缩略图

- 最多 4 个生成任务，同时图片解码 1 个、视频取帧 2 个、PDF 预览 1 个。
- 本地图片最多 128 MiB、32 百万像素；远端图片最多 10 MiB，压缩包中的封面读取最多 32 MiB。
- FFmpeg／PDF 输出最多 5 MiB，错误输出最多 8 KiB；取帧使用一个解码线程并限制单次分配为 64 MiB。HEIC 等外部解码图片也先探测像素、受同一个图片并发预算约束；这些不是操作系统级 RSS 限额。
- 一般生成失败负缓存 1 分钟，明确不支持／超限 24 小时；源变化使用新的缓存 key。旧零字节缓存不会永久阻止重试。
- 同 key 任务合并，待处理 key 有数量上限；原子写使用唯一临时文件，避免固定 `.tmp` 冲突。

### 字幕

- 外挂字幕最多 16 MiB，编码检测只读 64 KiB 前缀，处理 UTF-8 截断尾部。
- WebVTT 直接流向唯一临时文件，输出最多 64 MiB、stderr 最多 8 KiB，成功后才原子发布。
- 同字幕共享转换，最多两个进程；某个客户端取消不终止仍有用的转换，服务器生命周期和五分钟超时约束任务。

已验证超限图片在解码前拒绝、超大字幕拒绝、并发字幕只转换一次、负缓存到期恢复、并发缓存写入无撕裂及失败清理。尚未测量目标 NAS 多会话下的峰值 RSS、FFmpeg RSS 和吞吐。

## HLS：R11

时间轴保存在 `cache/hls/timelines`，key 包括来源标识、真实大小／纳秒 mtime、输出参数、切片策略、工具身份和缓存版本。载入校验 checksum、连续时间、正时长和 packet 数；损坏或旧版本重新探测，源变化不复用旧结果。命中持久化时间轴不占用探测进程槽。

持久化时间轴默认最多 32 MiB／1024 个文件，空闲超过 30 天清理；单条读取最多 16 MiB。每个来源默认最多 32768 个片段（库 Config 可调整），内存中的时间轴数量受会话上限约束。数据目录通过 OS 文件锁独占；进程退出自动释放锁，下次启动清理遗留的私有片段目录。

片段仍按需生成，不跨重启保留。完成片段遵守默认 512 MiB LRU 配额；正在生成的临时输出额外占用磁盘，受并发和超时约束，并非硬磁盘配额。不要把这个缓存限制当作操作系统级磁盘限额。

重启复用、损坏重建、源变化失效、同目录独占及遗留清理已有测试；完整 HLS 回归继续覆盖 seek、分集片段、音画时序、取消和多个播放令牌。真实 SSD／机械盘／NFS／SMB 上的首次 packet 扫描读取量、首帧及 seek 分位数仍待实测。

## 搜索和离线前端：R12

Preact/htm 3.1.1 分发包及 hls.js 1.6.13 已固定到 `web/vendor`，包含上游来源、SHA-256 和许可证；由 embed.FS 提供，脚本 CSP 只允许 self，维持零构建。更新依赖时同时更新文件名、导入路径及 manifest，避免旧浏览器缓存错用。远端海报和在线识别仍需要网络。

可重复基准：

```sh
go test ./store -run '^$' -bench BenchmarkSearch -benchtime=3x -count=1
```

本机 Darwin/arm64、Apple M4、Go 1.27.3，合成 SQLite 索引，单查询返回最多 200 条，三次采样均值：

| 条目数 | `音乐`（双字 LIKE） | `精选合集`（FTS） | `作品`（高频双字 LIKE） |
| --- | --- | --- | --- |
| 100,000 | 17.33 ms | 1.50 ms | 17.24 ms |
| 1,000,000 | 169.13 ms | 15.10 ms | 175.00 ms |

每次查询约分配 251–258 KiB。这个基准包含标题分布与结果排序成本，不是 NAS 文件系统或生产查询延迟承诺。暂保留短词 LIKE；是否增加双字索引需结合真实词频、写入成本、磁盘体积和 NAS 数据再决定，不引入独立搜索服务。

艺术家和图书系列等新的聚合语义仍按实际需求扩展，本轮没有引入动态 Go plugin。

## 实机部署补充：大响应缓存的启动清理

在一次实机部署的约 9.4 GiB 数据库、75,318 条 ThePornDB 缓存上，首次升级暴露了启动清理慢的问题。旧清理语句按 key 查询后读取 at；由于 at 位于大响应 BLOB 后面，即使记录全都新鲜，也会遍历大量溢出页。已增加覆盖索引 `cache_expiry(at,key)`，先从索引筛出过期 key，再删除对应记录。索引是增量 DDL，不改变 schema 版本或清空缓存；首次建索引仍有一次性的扫描成本。

本机 100 条、每条 1 MiB 的新鲜缓存，三次采样平均：旧实现 15.91 ms／次，索引实现 0.572 ms／次（约 28 倍）；对应命令为 `go test ./store -run TestCachePrune -bench BenchmarkCachePruneFreshLargeResponses -benchtime=3x -count=1`。回归验证只清理指定前缀中的过期记录，不删除其他前缀或新鲜缓存。
